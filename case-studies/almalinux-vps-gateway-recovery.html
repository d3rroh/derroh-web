AlmaLinux VPS Non-Standard Gateway Recovery

AlmaLinux systemd-networkd ip route OVH

A VPS running AlmaLinux lost network connectivity after a routine reboot. The provider (OVH-style Hetzner networking) uses a non-standard gateway configuration that doesn't sit on the same subnet as the host's assigned IP — a setup that trips up default network configuration tooling.

Recovery

With no network access, I worked through the provider's console to manually restore connectivity using raw ip commands — setting the correct route to the non-standard gateway directly, bypassing the assumptions baked into standard DHCP/NetworkManager configs.

Making It Permanent

A manual ip route fix doesn't survive a reboot, so I translated the working configuration into a persistent systemd-networkd definition, ensuring the server would come back online correctly on its own after any future restart — without needing manual console intervention again.
