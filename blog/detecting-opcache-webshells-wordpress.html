Detecting OPcache-Disguised Webshells in WordPress

security wordpress malware opcache

One of the more effective WordPress persistence techniques I've encountered in incident response is a PHP webshell disguised as a legitimate OPcache-related file, placed deep enough in the filesystem to avoid a casual look.

How the Disguise Works

Attackers name the malicious file to closely resemble OPcache cache artifacts or core WordPress files, and place it in a directory depth where administrators rarely browse manually. Combined with a file upload bypass as the initial entry vector, this can sit undetected for a long time.

Filesystem Patterns That Give It Away

  • File modification timestamps that don't align with the last legitimate WordPress core or plugin update
  • PHP files present in upload directories that should only ever contain media
  • Files with names that are near-identical to legitimate system files but subtly off
  • Unexpected outbound connections traced back to a specific file when checked against server logs

Remediation Playbook

A full filesystem audit combining signature-based scanning (ClamAV) with manual review catches what automated tools alone miss — disguised webshells are specifically designed to evade generic scanners. Once found, remove the backdoor, then harden upload restrictions and file permissions so the same entry vector can't be reused.
