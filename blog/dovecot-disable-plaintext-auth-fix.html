Dovecot disable_plaintext_auth: Making the Fix Survive Container Restarts

dovecot docker-mailserver email containers

A common mistake when hardening a docker-mailserver instance is editing dovecot.conf directly inside the running container — the fix works immediately, then silently disappears the next time the container restarts or is recreated from the image.

Why It Disappears

Container filesystem changes outside a mounted volume don't persist across container recreation. docker-mailserver regenerates or overwrites parts of its config from the base image on startup, so a manual in-container edit to disable_plaintext_auth gets clobbered the moment the container restarts.

The Correct Fix

The reliable approach is using docker-mailserver's supported override mechanism — a user-patches.sh script that runs on every container start and re-applies the configuration change idempotently, rather than relying on a manual edit surviving. This makes the fix part of the container's startup process instead of a one-time change that silently regresses.
